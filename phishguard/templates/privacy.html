How your data is handled

PhishGuard runs on your own computer. This page describes what this installation stores and sends.

What is stored

  • A shortened copy of the address: scheme, host, path (truncated) and query parameter names. Query values, login details and the part after # are removed.
  • A keyed fingerprint of the full address, which cannot be reversed into the address.
  • The verdict, findings and the status of each check.
    • {% if store_normalized %}
  • This installation is configured to also store the normalised address (without login details or fragment) because STORE_NORMALIZED_URL is enabled.
    • {% endif %}

Who can see it

History is tied to an anonymous identifier in this browser's session cookie. Other browsers using the same installation cannot see these records, and the database stores only a keyed hash of the identifier. Clearing your cookies starts a new, empty history.

How long it is kept

Every record is deleted automatically {{ retention_days }} day{{ "s" if retention_days != 1 }} after the scan. You can delete individual records or your whole history at any time from the History page.

What is sent elsewhere

{% if intel_configured %}

{{ intel_configured }} threat-intelligence service{{ "s are" if intel_configured != 1 else " is" }} configured. For each scan, the normalised address (including its path and query, but without login details or fragment) is sent to {{ "those services" if intel_configured != 1 else "that service" }} to check it against their lists. Their own privacy terms apply.

{% else %}

Nothing. No threat-intelligence service is configured, so addresses never leave this computer.

{% endif %}

The submitted link itself is never opened, downloaded or contacted by PhishGuard.

Logs

The application log records scan IDs and verdicts, never the scanned addresses. Query strings are removed from request log lines.
