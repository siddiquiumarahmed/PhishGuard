How PhishGuard decides

Every scan combines up to three methods. This page is generated from the same rule definitions the detector uses.

MethodsVerdictsRisk indexRulesLimitations

Methods

{{ icon("list", "icon icon--sm") }} Address rules
The address is parsed exactly as a browser would read it, then checked by {{ rules | length }} rules for deception techniques. This always runs and needs no network access.
{{ icon("globe", "icon icon--sm") }} Threat intelligence
Optional lookups against Google Safe Browsing, Google Web Risk and PhishTank when configured. A failed or skipped lookup is reported as such and never counts as a clean result.
{{ icon("model", "icon icon--sm") }} Machine learning
An optional scikit-learn model trained on a labelled dataset using the same address features. Its score is an uncalibrated estimate. On its own it can raise a verdict to Suspicious at most, and it never lowers a verdict.

PhishGuard never opens the submitted link. Page content, redirects and downloads are therefore not inspected.

Verdicts, in order of precedence

The first condition that applies decides the verdict.

  1. {{ verdict_badge("confirmed_malicious") }} A threat-intelligence service returned a verified listing.
  2. {{ verdict_badge("high_risk") }} A critical finding; two or more high findings; or a high finding corroborated by a medium finding, an ML score above threshold, or an unverified listing.
  3. {{ verdict_badge("suspicious") }} A high finding; two or more medium findings; an unverified listing; or an ML score above threshold.
  4. {{ verdict_badge("inconclusive") }} Nothing above applies, but a necessary check did not complete: rules failed, or a configured blocklist lookup failed.
  5. {{ verdict_badge("no_threat_detected") }} Otherwise. The checks that actually ran are always listed.

Heuristic risk index

A 0–100 number computed by adding a fixed weight for each finding and capping at 100. It helps compare scans; it is not a probability and has not been calibrated against real outcomes. The verdict is decided by the precedence above, not by this number.

Known limitations

  • Brand protection covers a built-in list of frequently impersonated organisations only.
  • Registered domains are computed from a compact offline suffix list, not the full Public Suffix List.
  • Compromised legitimate sites and brand-new phishing domains with neutral names can look clean.
  • Shortened links are not expanded, because doing so would contact the attacker's infrastructure.
